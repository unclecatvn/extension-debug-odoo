Odoo debug mode: 4 ways to turn on developer mode

Odoo debug mode, which Odoo's own menus call developer mode, adds the technical tools to the page: the bug menu in the top bar, the Technical menu in Settings, and the field names in every tooltip. The shortest way in is to add ?debug=1 to the URL. Here are all four ways, what the assets and tests variants do, how to turn it off, and what debug mode still does not tell you.

Turn on Odoo debug mode

1. In the URL: ?debug=1

Add ?debug=1 right after /odoo in the address bar and press Enter:

https://example.odoo.com/odoo?debug=1

It works from any screen of the backend, and Odoo keeps it for the rest of the session: you do not add it again on the next page.

2. In Settings

Open Settings, scroll to Developer Tools at the bottom of the page and click Activate the developer mode. The two links beside it turn on the assets and tests variants. The section shows once at least one app is installed.

3. In the command palette

Press Ctrl+K (Cmd+K on a Mac), type debug and pick Activate debug mode. The palette offers the command only when the word is typed in full.

4. With a browser extension

Odoo Debug, a free extension for Chrome, Edge and Brave, switches between Off, Debug and Assets from its toolbar icon, or with Alt+Shift+D on any Odoo page. No URL to edit, and it works the same on Odoo.sh, on-premise and localhost.

The modes: debug, assets, tests

URLWhat it does
?debug=1Developer mode: the bug menu, the Technical menu, field names in tooltips.
?debug=assetsThe same, with the JavaScript and CSS served unminified and file by file, to read and debug front-end code. Pages load slower.
?debug=testsThe same, with the test assets loaded, to run test tours from the browser.
?debug=0Developer mode off.

Turn off debug mode

Any of these: put ?debug=0 in the URL, pick Leave Debug Mode in the bug menu, click Deactivate the developer mode in Settings, or run Deactivate debug mode from the command palette.

What debug mode shows

  • The bug menu in the top bar. On a record: Metadata (its ID, XML ID, who created it), Data (the raw values), Set Default Values. On a view: the view's own form to edit it, and its Computed Arch after inheritance. Anywhere: Open View, Regenerate Assets and, for administrators, Become Superuser.
  • Settings → Technical: models, fields, views, actions, record rules, scheduled actions, system parameters.
  • Field tooltips: hover a field label to see its technical name, model, type and widget.

Debug mode gives no extra rights. Access rights and record rules apply as before; it only shows the tools that the user's groups already allow.

What debug mode does not show

Developer mode shows what is on the screen. The questions that take the time are about why:

  • Which module adds this field, and which inherited view made it read-only or invisible?
  • Which RPC call failed, with what payload and what Python traceback?
  • Which access right or record rule refuses this user, and which group would allow it?
  • Which request fires the same SQL query two hundred times?

Answering those from developer mode means opening views one by one, reading the server log and testing rules by hand.

Odoo Debug answers them on the page

A panel on the Odoo page itself, in nine tabs: record and field inspector, view inheritance, RPC log, access rights and record rules, translations, SQL profiler. Free, source on GitHub, no tracking. For Odoo 18, 19 and 20.

Questions

Is Odoo debug mode the same as developer mode?

Yes. The URL parameter is debug, Settings says "developer mode", the command palette says "debug mode": one feature, three names.

Does debug mode slow Odoo down?

Plain ?debug=1 barely does. ?debug=assets does: the browser fetches every JavaScript and CSS file on its own, unminified. Use it while debugging front-end code, then go back to ?debug=1.

Can every user turn on debug mode?

Any internal user can add ?debug=1 to the URL. What they see in the menus still depends on their groups: the Technical menu and Become Superuser are for administrators.
