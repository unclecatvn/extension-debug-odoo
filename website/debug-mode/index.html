Odoo debug mode:4 ways to turn it on

Debug mode, which Odoo's own menus call developer mode, adds the technical tools to the page: the bug menu, the Technical menu in Settings, field names in every tooltip. The shortest way in: add ?debug=1 to the URL.

// turn it on

Turn on Odoo debug mode

Pick one, once: Odoo keeps the mode for the rest of the session, page after page.

  1. In the URL

    Add ?debug=1 to the end of the address and press Enter, from any backend page. If the address already has a ?, add &debug=1 instead.

    example.odoo.com/odoo/sales?debug=1

  2. In Settings

    Open Settings, scroll to Developer Tools at the bottom and click Activate the developer mode. The links under it turn on the assets and tests modes. The section shows once at least one app is installed.

  3. In the command palette

    Press Ctrl+K (Cmd+K on a Mac), type debug and pick Activate debug mode. The command shows only when the whole word is typed.

  4. With a browser extension

    Odoo Debug switches between Off, Debug and Assets from its toolbar icon, or with Alt+Shift+D on any Odoo page: Odoo.sh, on-premise or localhost. Free, for Chrome, Edge and Brave.

// modes

Debug, assets, tests

The value of debug in the URL picks the mode, and the same parameter turns it off.

The modes

?debug=1
Developer mode: the bug menu, the Technical menu, field names in tooltips.
?debug=assets
The same, with the JavaScript and CSS served unminified, file by file, to debug front-end code. Pages load slower.
?debug=tests
The test assets, to run test tours from the browser.
?debug=0
Off.

Turn it off

  • ?debug=0 in the URL
  • Leave Debug Mode in the bug menu
  • Deactivate the developer mode in Settings
  • Deactivate debug mode in the command palette
  • Off from the Odoo Debug icon, or Alt+Shift+D
// what you get

What debug mode shows, and what it does not

What it shows

  • The bug menu in the top bar. On a record: Metadata, Data, Set Default Values. On a view: the view itself, and its Computed Arch after inheritance
  • Open View, Regenerate Assets and, for administrators, Become Superuser
  • Settings → Technical: models, fields, views, actions, record rules, scheduled actions, system parameters
  • Field names in tooltips: hover a label for its technical name, model, type and widget

No extra rights: access rights and record rules apply as before.

What it does not

  • Which module adds this field, and which inherited view made it read-only?
  • Which RPC call failed, with what payload and what Python traceback?
  • Which access right or record rule refuses this user?
  • Which request runs the same SQL query two hundred times?

Developer mode shows what is on the screen; those are about why. Without a tool, they mean opening views one by one, reading the server log and testing rules by hand.

Questions

Is Odoo debug mode the same as developer mode?

Yes. The URL parameter is debug, Settings says "developer mode", the command palette says "debug mode": one feature, three names.

Does debug mode slow Odoo down?

Plain ?debug=1 barely does. ?debug=assets does: the browser fetches every JavaScript and CSS file on its own, unminified. Use it while debugging front-end code, then go back to ?debug=1.

Can every user turn on debug mode?

Any internal user can add ?debug=1 to the URL. What they see in the menus still depends on their groups: the Technical menu and Become Superuser are for administrators.

Does it work the same on Odoo.sh and on-premise?

Yes: the parameter, the Settings link and the command palette are part of Odoo itself, wherever it runs.
